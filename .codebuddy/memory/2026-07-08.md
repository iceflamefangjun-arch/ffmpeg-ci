# 2026-07-08

## clang-shell: live+x64 GitHub Actions 编译失败修复

### 根因 (root cause)
`env_config.sh` 里 `generate_msys2_tool_wrapper` 生成的 clang-cl/lld-link 包装脚本有路径转换 bug。
- pkg-config（MSYS2 下的原生 Windows 二进制）对 ffnvcodec 等模块会输出 **Windows 盘符路径**，例如 `-ID:/a/ffmpeg-ci/.../nv-codec-headers/include`。
- 包装脚本的正则 `^([-/][A-Za-z]+:)(/[a-zA-Z]/.*)$` 把 `-ID:/a/...` 错误拆成 opt=`-ID:` + path=`/a/...`，再 `cygpath -w "/a/..."` → `C:\a\...`（错误盘符，仓库在 D: 盘）。
- 结果 ffmpeg configure 的 nvenc 检查 `check_func_headers ffnvcodec/nvEncodeAPI.h ... -ID:/a/...` 报 `fatal error: 'ffnvcodec/nvEncodeAPI.h' file not found`，configure die：`ERROR: nvenc requested, but not all dependencies are satisfied: ffnvcodec`。
- 该 bug 同样会静默破坏 x264/fdk-aac/libmfx/zlib 等通过 pkg-config 拿到的 Windows 盘符 include 路径（被改写成错误盘符），导致这些依赖在 live 构建里被错误禁用。

### 修复
在包装脚本的 for 循环里，在 `-libpath:` 分支之前新增一个分支，处理「选项 + 已带 Windows 盘符的路径」：
`elif [[ "${arg}" =~ ^([-/][A-Za-z]+)([A-Za-z]:/.*)$ ]]; then` → 仅用 `cygpath -w` 规范化斜杠，不再把盘符冒号误判为选项/路径分隔符。
新增分支必须放在原 colon 分支（pattern 3）之前，且不干扰 Unix 路径（`/d/a/...`，走原 pattern 4，行为不变）与 `/LIBPATH:/d/a/...`（走原 pattern 3）。

### 验证
- `bash -n env_config.sh` 通过。
- 用独立脚本模拟各参数转换：`-ID:/a/...`→`-ID:\a\...`（正确 D 盘），`-I/d/a/...`→`-I\d\a\...`（不变），`/LIBPATH:/d/a/...`→`/LIBPATH:\d\a\...`，`/FoD:/a/...`→`/FoD:\a\...` 均正确。
- 该修复同时解决 live+x64 的 debug/release/static 三种配置（nvenc 检测代码路径相同）。player 构建不受影响（player 的 b.sh 硬编码 `--disable-nvenc`，且新分支只命中 Windows 盘符路径，player 不产生此类参数）。

### 结论
只改了 `env_config.sh` 一个文件（共享脚本），未改动 player 配置。live+x64 三配置应均可在 GitHub Actions (windows+msys2+clang) 编译通过。
